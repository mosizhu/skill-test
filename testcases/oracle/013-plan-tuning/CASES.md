## 前置条件

## 执行步骤

1. 通过 Mopheus 工单触发 `db-oracle-plan-tuning` skill
2. 传入参数:
   - `instance_host` = `oracle-rac_node01`

   - `action` = `analyze`（仅分析，不修改）
3. 等待诊断完成

## 预期结果

### 输出格式

```
## 执行计划分析报告
### SQL 基本信息
| 属性 | 值 |
|------|------|
| SQL ID | xxxxxx |
| SQL 类型 | SELECT |
| 执行计划 | 见下方 |
| 状态 | 有效 |

### 当前执行计划
| 行号 | 操作 | 对象 | 访问方式 | 成本 |
|------|------|------|----------|------|
| 0 | SELECT STATEMENT | - | - | 100 |
| 1 | NESTED LOOPS | - | - | 100 |
| 2 | INDEX RANGE SCAN | IDX_1 | 索引 | 5 |
| 3 | TABLE ACCESS FULL | TABLE_A | 全表扫描 | 95 |

### 问题识别
1. **TABLE_A 全表扫描**（行号 3）
   - 问题: 表 TABLE_A 全表扫描，成本 95
   - 原因: 缺少合适索引或统计信息过期
   - 影响: 大表扫描影响性能

2. **嵌套循环连接**（行号 1）
   - 问题: 嵌套循环连接适合小表，但 B 表数据量大
   - 原因: 数据量分布不均
   - 影响: 数据量大时性能急剧下降

### 优化建议
1. **高优先级**
   - 操作: CREATE INDEX idx_table_a_col ON table_A(column_name)
   - 预期效果: 全表扫描改为索引范围扫描，成本降低 90%
   - 风险: 低（仅添加索引，不影响业务）
   - 维护窗口: 无需维护窗口

2. **中优先级**
   - 操作: 考虑使用 HASH JOIN 替代 NESTED LOOPS
   - 预期效果: 连接操作优化，性能提升 20-30%
   - 风险: 中（需验证查询逻辑）
   - 维护窗口: 建议维护窗口

### 影响评估
| 指标 | 优化前 | 优化后 | 改善 |
|------|--------|--------|------|
| 执行时间 | X ms | Y ms | Z% |
| 逻辑读 | N | M | W% |
| 成本 | 100 | 10 | 90% |
```

## 通过标准

- 执行计划完整，包含行号、操作、对象、访问方式
- 问题识别有具体行号和原因
- 优化建议有 SQL 语句
- 风险等级明确
- 有预估的性能改善
